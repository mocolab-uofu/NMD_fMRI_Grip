#+TITLE: NMD Group Analysis With BayesfMRI 0.15.0 Area Filtering

* Purpose and analysis settings

Rerun the full group model for 40 participants (22 CTR, 18 DEP) using the
collaborators' first-level models previously converted to RDS by Yunong.
Run the formal analysis directly, as requested; there is no pilot mode or
separate validation job. Ordinary input and completion checks are part of the
formal scripts. Historical scripts 01-03 and their results remain available.

| Setting | Value |
|---------+-------|
| BayesfMRI | 0.15.0, upstream commit 6f5b08fa498fe87af1f77a72acc63d28645ab198 |
| R / INLA / ciftiTools | 4.4.1 / 24.12.11 / 0.19.0 |
| Minimum areas | 20, 30, 40 squared model-coordinate units |
| gamma / alpha / alpha_nested | 0 / 0.05 / NULL |
| nsamp_theta / nsamp_beta | 50 / 100 |
| New run seed | 20261025 |
| Sampling workers | 4; one INLA/BLAS/OpenMP thread per worker |

Retain the existing five-column design without an additional intercept:
=group_CTR, group_DEP, age, sex, upgrade=. Do not center or scale covariates.
Retain all five rows of the existing contrast matrix and excursion types
=>, >, !=, !=, !==. The historical "average" names refer to group coefficients
at zero-valued covariates; they are not raw sample averages.

The new single-alpha mode replaces the old nested alpha 0.05/0.01 call for this
run only. The package's area procedure uses a common weighted ordering and
recomputes the joint set as small components are excluded. It is not simply a
post-hoc deletion of clusters in an old activation map, and its sets need not
be nested across area thresholds. Opposite directions form separate clusters.
Keep the pinned package's inference and theta-weighting implementation intact.

Areas are sums of lumped FEM vertex areas on the reference first-level model
mesh. Do not describe them as anatomical mm^2 without establishing the mesh
coordinates and surface provenance. The inflated/very-inflated GIFTI files
below are display surfaces, not replacement geometries for the area calculation.

The two refilter manifests retain the original sample source, mesh, weights,
threshold-specific diagnostics and filtering provenance. Keep them in
=analysis_records/=; the area-30/40 model objects refer to these files.
The =BayesGLM2-<GENERATED>= suffix is an automatic unique directory name from
R's =tempfile()=, not an analysis parameter or Slurm ID. All files remain on
persistent project storage despite the function's name.

The public package accepts one area threshold per call. Script 04 therefore
calls BayesGLM2 once with area 20 and a persistent sample directory, saves the
complete object, then invokes =BayesfMRI:::excursions.mc.no.spurious= for 30 and
40. Each call uses the original valid mask, reference mesh, theta weights and
sample paths. The internal API is tied to the pinned source revision. Update
the cortical PPM, activation, filter diagnostics and CIFTI data together; retain
the original manifest and give each derived object its own manifest path.

Completion checks establish that coefficients and voxel results are identical
across the three objects, CIFTI data match the masked mesh activations, all final
signed clusters meet the threshold, and posterior checksums remain unchanged.
Empty activation is a valid result. Strict nesting across thresholds is not
required. These checks use the formal outputs, not a separate analysis run.

If filtering fails after the area-20 checkpoint has been saved, diagnose the
failure and resubmit script 04 with the original run directory as argument 2.
It loads that checkpoint and checks input provenance instead of sampling again.
An interrupted fit with only partial samples is not automatically resumable;
the script stops rather than silently drawing a second set in the same folder.

The R seed and cortical sampling seeds are recorded. The package's legacy
voxel sampler does not expose the same explicit seed handling, so this record
does not imply bitwise reproducibility of the entire mixed model across runs.

* Directory organization and provenance

The shared run uses =full/group_area_20_30_40/= with =analysis_records/=,
=posterior_samples/=, =results/=, =plots/= and =tables/=. The previous
=full/job-1558105/= run and its title-correction replot are consolidated here.
Only the corrected 95 main PNGs and 30 legends remain in =plots/=.

The organization operation updates active paths in model objects, manifests,
run information and CSV inventories. It preserves numerical results, posterior
sample bytes and corrected image bytes; no fitting or plotting is required.
RDS file checksums change when stored paths change. Current model checksums and
the before/after migration checksums are stored in =analysis_records/=;
pre-migration plotting checksums remain with the historical plot-job records.
Historical logs, submitted code snapshots and original calls retain their
original text. The combined =run_record.org= records the path mapping and the
analysis and plot jobs that actually generated the results.

The one-time maintenance script
[[file:scripts/06_organize_area_outputs.R][06_organize_area_outputs.R]] performs this migration on Hazel using the
existing environment and =NMD_CODE_COMMIT=. It checks that no user jobs are
queued or running, stages path-only RDS replacements, compares all numerical
contents, and reads checksums for the 500 posterior files and corrected figures.
Temporary recovery copies remain on Projects until final checks pass and are
then removed. It stops if the destination or a partial migration already exists;
inspect that state before any retry. It does not submit a Slurm job or invoke
analysis, filtering or rendering functions. Completed results require no further
execution of this maintenance script.
